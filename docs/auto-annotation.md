# 模型自动标注

在“数据集处理 → 模型自动标注”中选择“本地 PT 标注”或“远程 STAR 标注”。两种模式都在本机原图旁生成 VOC XML，不修改图片。

## 本地 PT 标注

选择本机图片文件夹、训练后的 Ultralytics 目标检测 PT 模型，点击“开始 PT 标注”。默认自动使用本机 yolo26 环境，也可以填写 Python 解释器路径。

- 每张图片旁生成同名 VOC XML，框使用原图像素坐标，类别名称来自模型。图片不修改。
- 默认置信度 0.5、IoU 0.7、推理尺寸 640；支持设备、类别编号筛选和递归扫描子目录。
- 已有 XML 默认跳过。“备份后覆盖”会先复制旧 XML 到图片根目录 `.annotation_backups/<任务编号>/`，保持相对路径。需要恢复时将备份 XML 复制回对应图片目录。
- 无目标时默认生成不含 object 的 XML；请人工复核，未检出不代表一定没有目标。
- 同一目录存在 `a.jpg` 与 `a.png` 等同名图片时会在写入前报错，避免共用 `a.xml`。
- 终止任务会停止推理子进程，已生成的 XML 保留。逐张输出进度，失败图片记录在日志中。

当前支持 Ultralytics 检测模型（包括 YOLO26），不支持旧 YOLOv5 仓库格式、分割、旋转框和分类模型。自动标注结果需要在标注工具中人工复核后再用于训练。

## 远程 STAR 标注

1. 选择本机图片目录和本机 STAR 模型，填写盒子 IP、端口、用户名和密码。IP 输入框可选择已有 SSH 连接，密码默认记住，也可清除保存。
2. 点击“读取 STAR 类别”查看/填充内嵌类别；留空时运行会自动读取。无法识别元数据时需要手动填写，每行一个或逗号分隔，顺序必须与模型类别 ID 一致，也支持从 0 开始的 `0: MARK` 格式。不会猜测类别名。
3. 点击“测试 SSH 连接”，成功后点击“开始 STAR 标注”。连接参数变更后需重新测试；测试凭据有效期为 30 分钟。SSH 测试仅验证连接，加载时才检查 TensorRT/CUDA 等推理环境。

复用远程实时推理内置的 STAR 读取、letterbox、YOLO26 分头输出解码与分类别 NMS；当前不支持其他厂商输出格式、旋转框、分割或分类 STAR。模型输入尺寸来自 TensorRT 引擎，本地 PT 的推理尺寸/设备/Python 参数对 STAR 模式不生效。每张图片完整推理，不采用视频的实时跳帧策略。XML 存原图坐标和类别名称，不存画过框的图片。对比现场效果时，请将置信度和 IoU 设置为实时推理使用的相同数值。

盒子需已有与引擎匹配的 TensorRT、CUDA、NumPy、OpenCV，可指定远端 Python 解释器；本机不需要 TensorRT 或 Ultralytics。脚本、模型自动上传到独立临时目录，模型只加载一次，逐张上传图片覆盖临时输入，避免占满盒子磁盘。结束、异常或手动终止会清理本次上传的文件；SSH 完全断开可能无法清理，会输出临时目录以便手动检查。运行过程中不要关闭平台，STAR 自动标注不是独立 tmux 后台任务。

与 PT 模式共用递归扫描、类别筛选、跳过/备份覆盖、空 XML、逐张进度、终止及运行历史。已有 XML 备份在本机 `.annotation_backups/<任务编号>/`；终止保留已经生成的 XML。协议异常、类别越界会停止，不会当成负样本生成空 XML。图片解码失败会记录失败图片，其余继续；未检出的空 XML 仍需人工复核，可打开 X-AnyLabeling 修改后用于训练。
