# 桌面分发依赖审计

日期：2026-10-31。目标：可分发桌面程序，而非云端多人 Web 服务。

## 结论

基础数据处理不依赖开发者电脑的 tools 目录或 conda 环境。但当前安装包不能称为“所有功能零配置”：AI 库此前被主动排除，第三方打包工具、量化容器和外部软件也未随包提供。
本轮准备了可选 AI 集成构建和冻结程序 worker 支持，尚未生成并验收大型 AI 安装包。源码检查通过不代表四平台发行包已经验证。

| 功能 | 平台已包含 | 仍需的用户输入／环境 |
| --- | --- | --- |
| 抽帧、裁剪 | 处理实现、资源调度；打包显式收集 imageio-ffmpeg | 用户视频、系统桌面／视频支持 |
| 数据划分、提取负样本、图片去重、量化数据集制作 | 本机逻辑和远端上传脚本 | 用户图片和标签；远端操作需 Python，部分需 Pillow |
| PT 检测、反向标注 | 适配代码与 worker | PyTorch、Ultralytics 和用户权重，GPU 可选 |
| YOLO26 ONNX 导出 | 内置切头导出 worker | 兼容的 PyTorch、Ultralytics、ONNX 等库与用户权重 |
| 经典 YOLOv5 导出 | 平台适配逻辑 | 与旧权重匹配的 YOLOv5 源码及专用环境 |
| STAR 打包 | 配置逻辑、内置 TOML 模板 | 匹配目标操作系统的 package_tool，当前未随包提供 |
| STAR 类别读取 | 纯 Python 解析 | 用户 STAR；无需 TensorRT、CUDA 或 SSH |
| SSH 推理、TensorRT 构建、训练 | SSH 客户端、脚本、任务与日志逻辑 | 用户服务器／盒子及相应 GPU 驱动、TensorRT／训练运行库 |
| Docker ONNX 量化 | 参数、挂载校验和执行适配 | Docker、合法可分发的 EasyONNXQuant 镜像／安装包 |
| X-AnyLabeling、Antigravity | 可选启动入口 | 对应软件合法安装程序，不影响其他功能 |

模型、图片、视频、标签、授权码属于用户输入，不应内置为公共数据。
密码、历史连接、激活记录、管理员签发私钥不能用于制作默认配置，也不能随仓库或安装包分发。

## 本轮已优化

- TOML 模板内置，路径留空即可。显式填写错误模板时继续报错，不擅自回退。
- 新安装不默认连接开发者 IP 或用户名。
- 训练源码和模型路径不再强制覆写；源码留空使用服务器已安装的 Ultralytics，旧场景配置中的路径保留。
- 本地 AI 可选任意 Python，无需固定 conda 环境名；AI 构建可使用自身运行库，旧 yolo26 环境查找仅作兼容回退。
- 冻结后的标注／导出 worker 通过专用入口启动，不把桌面程序当成普通 Python 解释器。
- 本机设置与 `python run.py --dependencies` 显示依赖清单，不自动安装、不读取用户数据、不连接 SSH/Docker。
- PyInstaller 支持 standard／ai 配置，随包生成构建类型和依赖精确版本清单；AI 配置缺包或未确认许可审阅时拒绝构建。

## AI 构建（尚待实际验收）

使用干净的 Python 3.11 构建环境。先按 PyTorch 官方说明选 CPU 或对应 CUDA 的依赖来源，再安装 requirements-ai.txt。
requirements-ai.txt 是版本范围输入，不是已验收锁文件；模型兼容验收后，应固定解析到的全部依赖版本与校验值。
禁止复制开发者当前 conda 环境整体分发。

```bash
python -m pip install -r requirements-ai.txt
YOLO_BUILD_PROFILE=ai YOLO_AI_LICENSE_ACKNOWLEDGED=1 python -m PyInstaller --noconfirm --clean packaging/yolo_data_platform.spec
./dist/YOLO-Data-Platform/YOLO-Data-Platform --check --require-ai
```

macOS 改为运行 app 内的可执行文件，Windows 使用对应的环境变量语法和 exe。
CPU、CUDA、macOS Intel／Apple Silicon 要分别验收；不能承诺一个 AI 依赖组合适合全部平台。
当前 Windows/macOS 发行包仍未完成发行者签名／Apple 公证。

## 尚未消除的依赖及所需条件

1. package_tool：需要可再分发授权、版本信息和各目标系统的二进制／源码，不能把现有 Linux 程序视作跨平台工具。
2. EasyONNXQuant：当前容器内版本为 0.2.3，安装元数据未声明许可和主页。需确认可分发来源并固定镜像／wheel 校验值，才可建立受控镜像或离线资源包。
3. Ultralytics：按所选版本遵守 AGPL 义务或取得相应企业许可。构建变量只表示完成审阅，不是授予许可。
4. 外部软件与旧权重专用源码：逐项确认许可、固定版本及目标系统，不直接收集开发者硬盘内容上传。

完整版验收应覆盖：干净系统无 Python/conda、基础数据处理、PT CPU 推理、反向标注、ONNX 导出、STAR 打包及盒子实际加载、升级不丢用户配置。
Linux 中文输入法还依赖与所打包 Qt 匹配的输入法插件／系统输入服务；此前的 XIM 回退未做真实搜狗输入验收，也应纳入干净系统测试，不能仅凭启动检查宣称已支持。
