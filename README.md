# YOLO数据处理平台

一个面向本地数据处理脚本的可视化运行壳。左侧按分组维护功能，中间配置当前功能的数据路径和参数；具体处理逻辑按需逐个接入。

## 快速启动

### 通用启动方式

```bash
python3 run.py
```

运行后会直接打开“YOLO数据处理平台”桌面窗口。关闭窗口时，本地处理服务会自动停止。

桌面模式默认开启热更新。后续新增或修改功能时，后台 Python 文件以及已构建的前端界面会被自动识别并加载，不需要关闭应用重新启动；如果当时有数据处理任务正在运行，更新会安全等待到任务结束后生效。更新后当前窗口、已填写路径和本地保存的参数会继续保留。只有修改桌面外壳 `desktop.py` 或启动器 `run.py` 本身时，才需要重新启动一次。

### Windows

双击 `启动工作台.bat`。

### Linux / macOS

双击或运行 `./启动工作台.sh`。

如果提示缺少桌面组件，先执行 `pip install -r requirements.txt`。工作台只在本机内部通信，不对局域网或互联网开放。

Linux/X11 下如果系统使用 Fcitx 或搜狗输入法，而 PySide6 未附带匹配版本的 Fcitx 插件，启动器会自动改用 Fcitx 的 XIM 兼容通道。启动日志出现 `桌面输入法模式：xim` 即表示兼容模式已启用。需要手动指定时，可设置环境变量 `PROCESSING_VIEW_QT_IM_MODULE`。

仍需要浏览器模式时，可以运行 `python3 run.py --web`，访问地址保持为 `http://127.0.0.1:8765`。

## 当前版本

- 分组支持新建、重命名、删除和上下排序
- 功能支持跨分组移动、同组拖拽排序，以及放入“未分组”
- 删除分组只解除归属，不会删除分组内的功能
- 功能名称、路径和参数定义仍可随时修改
- 为每个功能定义任意数量的文件/文件夹路径
- 为每个功能定义文本、密码、数字、开关和选项参数
- 系统文件/文件夹选择窗口
- 普通参数值自动保存在当前应用中；密码参数只在内存中使用，不写入本地配置
- 统一的一键运行入口和运行输出区
- 不同功能可同时运行；模型训练还支持同时启动多个独立任务，可分别查看日志和终止
- 顶部“运行中 N 项”显示任务列表，可按任务单独终止；切换页面不会停止训练
- 顶部“运行历史”汇总所有功能最近完成的 5 条记录；正在进行的模型训练会置顶显示“正在运行”，不限数量且不占这 5 条名额。每个功能页面底部还会独立显示本功能最近 5 条已结束历史（成功、失败和终止），可展开查看时间、输入/输出位置和日志，也可手动删除单条记录（不会删除任务输出文件）。某个功能的第 6 条已结束记录只会删除该功能最早的一条，不影响其他功能。本机文件为 `runtime/run_history.json`，不保存 SSH 密码
- 任务成功完成时显示系统通知气泡，约 5 秒后自动关闭；桌面环境不支持系统托盘时自动使用非阻塞弹窗备用方案
- 当前远程训练仍依赖桌面平台保持运行，关闭平台会请求终止任务；tmux 脱离平台持久运行尚未接入
- 视频抽帧、视频裁剪、YOLO 划分和远程推理均支持终止；已完成的文件保留，裁剪临时文件会清理
- 极简处理器注册接口
- Python 一键启动的独立桌面窗口
- 桌面原生文件/文件夹选择窗口
- 后续功能支持热更新；任务运行中会延迟更新，避免中断处理

## 已接入功能

- 图片智能去重
  - 面向视频抽帧和 YOLO 训练数据，按文件名中的帧序号分组并依次分析，避免把不同视频或工序顺序混在一起比较
  - 使用画面灰度、边缘和颜色分布综合判断相似度；轻微变化会持续累积，达到差异阈值后自动保留
  - 每段序列强制保留首尾帧，并通过“最多连续移除张数”周期性保留过程锚点，避免相似工序被整段删掉
  - 支持五档去重力度、最低保留比例；默认至少保留 40%，可根据现场视频重复程度调整
  - 图片旁存在同名 YOLO TXT、VOC XML 或 LabelMe JSON 时，类别组合不同的画面不会互相去重，移出图片时标注文件会同步移动
  - 不永久删除文件：重复图片移入图片文件夹旁的隐藏批次目录，选择“回滚最近一次”可恢复图片和标注
- Docker ONNX 量化
  - 使用本机已有的 `onnx2quant` 容器和容器内 `onnxquant` Conda 环境运行 `easyonnxquant.tool`；容器停止时自动启动
  - 支持先执行“测试 Docker 环境”，不填写模型路径也可检查容器、Conda 和量化工具
  - 本机 ONNX、量化图片和输出目录会按 Docker bind mount 自动转换为容器路径；当前容器挂载为 `/mnt/disk2/model/onnx2quant` → `/yzc/onnx2quant`
  - 默认 `type=yolo`、`limit=128`，支持 `mobilenet`、`custom`、minmax/entropy 和多行排除节点正则
  - 输出文件名留空时自动生成 `<输入模型名>_quant.onnx`，若文件已经存在则停止并提示，不覆盖已有模型
  - 量化日志实时显示并支持终止；当前容器缺少可用的 TensorRT/CUDA 动态库时，工具可回退到 CPU 完成导出
- 远程 TensorRT 引擎构建
  - 可在多行文本框中粘贴多个 AI 推理盒子上的 `*_quant.onnx` 绝对路径，每行一个；通过 `trtexec --best` 严格按文本行顺序逐个构建 `.plan`
  - 不再从本机检查或上传 ONNX；SSH 连接后在远端逐条检查，并把同名 `.plan` 和 `.trtexec.log` 生成在 ONNX 原目录
  - 开始前会统一检查远端文件和输出名冲突；中途失败时停止后续构建，已完成的 `.plan` 与日志会保留
  - 每个 ONNX 转换完成都会单独显示系统通知，内容包含当前序号、ONNX 文件名和远端 `.plan` 路径；全部完成后再显示总任务通知
  - 复用远程实时推理的 SSH 测试、设备指纹和密码记忆；默认连接 `wel@192.168.1.223:22`
  - 优先使用独立 tmux 会话；盒子未安装 tmux 时自动回退到 `setsid + nohup`，关闭本机平台不会终止远端构建
  - 支持 FP32、FP16、自动最佳精度、构建后性能测试、结果覆盖控制、终止任务和远端结果保留
- 本地 STAR 模型打包
  - 选择本机 TensorRT `.plan`，填写 `title` 和类别名称后，调用 `/mnt/disk2/code/gen_package/package_tool` 完成打包
  - 类别名称旁提供“自动识别类别”：从 PLAN 同目录及上级目录中的 `classes.txt`、`data.yaml`、模型元数据或已有 `trt.toml` 读取并按顺序填充；PLAN 二进制本身通常不保存语义类别名
  - 类别名称支持每行一个或中英文逗号分隔，自动忽略空项并去除重复项
  - 默认读取 `/mnt/disk2/code/gen_package/trt.toml`，运行时只生成一次性 TOML，不会覆盖原模板
  - 常改的 PLAN、title、labels 集中显示；硬件架构、CUDA 驱动、模型类型、精度、输入张量和颜色格式放在可折叠高级配置中
  - 始终在 `package_tool` 所在目录执行命令；若工具把 STAR 写到该目录，平台会自动移至 PLAN 同级目录
  - 运行前检查 PLAN、模板、可执行权限和全部 TOML 必需字段；未检测到有效 STAR 时明确报错，不会误报成功
  - 打包成功后把新生成的 STAR 路径及类别名称加入“远程实时 AI 推理”工作流待办；只有用户点击应用才会修改配置
  - 支持运行日志、终止、最近 5 条历史记录和任务完成系统通知
- Jetson ONNX 导出
  - YOLO26 参考 `export_onnx_cut.py`，使用本机 Conda `yolo26` 环境将 PT 权重导出为静态 batch=1、FP32、无 NMS 的切头 ONNX；YOLOv5 可指定源码仓库，调用其官方 `export.py` 导出静态 ONNX
  - 目标检测会导出三个尺度的框和类别共 6 个输出张量，供 Jetson/TensorRT 推理脚本直接解码，不等同于普通 Ultralytics 端到端 ONNX
  - 默认 Jetson/TensorRT NCHW、`imgsz=640`、`opset=12`，也支持分割、OBB、姿态、分类和 RKNN NHWC
  - 导出在临时目录完成并通过 ONNX checker 校验后才移入输出位置，不修改 PT 源文件，也不覆盖已有 ONNX
  - 导出成功后自动把新 ONNX 填入“Docker ONNX 量化”的输入模型字段，形成 PT → cut ONNX → INT8 ONNX 流程
- 本地 PT 视频检测
  - 在“AI 推理”分组中与远程 STAR 推理分开；选择本机 `.pt` 权重和视频，无需 SSH
  - 使用权重自带的类别名称，支持置信度、IoU、最大框数、CPU/GPU、预览参数
  - 带框画面支持暂停/继续、拖动进度、撑满窗口和终止；可选保存带框 MP4
  - 默认按原视频时间轴播放；当模型推理 FPS 低于源视频 FPS 时自动跳过已经落后的源帧，避免预览变成慢动作
  - 自动跳帧只减少实际推理的画面数量，不会改变时间轴；保存视频时会补齐时间帧，避免输出视频被压缩加速
  - 平台 Python 没有 Ultralytics/PyTorch 时，会自动查找本机 Conda `yolo26` 环境，用独立进程执行 PT 推理，无需把训练依赖装进桌面平台环境
  - 使用其他环境时可设置 `PROCESSING_VIEW_YOLO_PYTHON` 为该环境的 Python 可执行文件；若当前平台 Python 已安装 Ultralytics，则直接使用当前环境
  - 选择 GPU 推理前，请确认该环境的 PyTorch 能识别本机 CUDA 驱动；否则将推理设备设为 `cpu`
  - 保存视频发生进度跳转时，已有文件保留，但后续回看片段不继续写入该文件，避免不连续内容混在一起
- 视频切图
  - 调用 `tools/data_processing_toolkit/02-video_processing/batch_vedio2img.py`
  - 支持处理一个视频文件夹，或单个 MP4 视频
  - 支持按每秒张数或时间间隔抽帧
  - 支持“工序时间段高密度”模式：多个工序时间段内默认按 25 帧/秒抽取，其余片段按 5 帧/秒抽取，总量默认限制为 500 张；三个参数均可调整
  - 超过总量上限时优先完整保留工序段候选图片，再从普通片段沿时间轴均匀补足；若工序段本身超过上限，则在全部工序段中均匀取满上限
  - 必填“项目英文标识”和“场景英文标识”；即使源视频是中文名，输出子文件夹和图片名仍全部使用英文、数字与下划线
  - 图片名自动记录项目、场景、视频序号、实际基础抽帧密度、视频时间点和原始帧号，例如 `tcl_191_line2_station3_video01_fps2_t000000500ms_f00000005.jpg`；小数帧率中的 `p` 代表小数点
  - 按时间间隔抽取时同时记录间隔和实际密度，例如每 `0.5` 秒一张会标记为 `every0p5s_fps2`
  - 最大抽取数量为可选项；留空时按抽帧密度和有效时间段自动决定张数
  - 可直接设置有效时间段的开始和结束时间，例如 `01:30` 至 `02:40`
  - 时间支持秒数、`MM:SS`、`HH:MM:SS`；结束时间留空表示抽到视频结尾
  - 超过上限时默认在有效区间内均匀抽取，也可选择从前往后抽取
  - 输出目录可选；留空时在原视频旁创建结果文件夹
- YOLO 数据集划分
  - 功能内分为“数据集划分”和“模型训练”两个页面，可直接切换
  - 增加数据集任务类型：目标检测、旋转目标检测、分割、分类
  - 当前已实现目标检测；其余模式保留入口，选择后会提示尚未接入
  - 默认使用 VOC XML，并自动转换成 8 位小数的 YOLO TXT；也支持已有 YOLO TXT 和仅图片
  - 将所选输出路径作为父目录；数据集子文件夹名称默认留空，运行时自动生成，例如 `yolo_train_20260922_163015/`，手动填写时优先使用自定义名称
  - 在数据集子文件夹中生成平铺的 `train/`、`val/`，图片与同名 TXT 标签放在一起
  - VOC XML 转换结果保存在 XML 文件夹同级的 `txts/`（例如 `Annotation/xmls` → `Annotation/txts`），方便检查和复用
  - 支持可选负样本文件夹；正、负样本分别按相同比例和随机种子划分，负样本自动生成空标签
  - 自动生成绝对图片路径的 `train.txt`、`val.txt`；`编号: 类别名` 格式的 `classes.txt` 放在数据集根目录，与 `Annotation/` 同级
  - 在图片与标签目录的共同数据集根目录生成 `data.yaml`；`train`、`val` 使用对应索引文件，当前无独立测试集时 `test` 使用 `val.txt`
  - `data.yaml` 的 `nc` 自动填写类别数量，`names` 按 XML 或 `classes.txt` 中的实际类别名称生成
  - SSH 信息留空时自动在本机处理；填写服务器 IP、用户名和密码后自动切换到远程模式，图片、标签、负样本和输出位置均填写服务器上的路径
  - 远程执行前必须先点击“测试 SSH 连接”；连接状态、设备指纹和具体失败原因会直接显示在运行区
  - 默认开启“记住 SSH 密码”，连接成功后密码加密保存在本机；也可取消勾选或随时清除已保存密码
  - 平台会把内置的无依赖划分脚本临时上传到远程 `/tmp`，在服务器本机处理数据，完成后自动删除脚本，不会把数据集下载到本机
  - 远程服务器只需 SSH 和可用的 `python3`；可通过“远程 Python 解释器”填写虚拟环境中的 Python 路径
  - 远程模式同样支持全平台“终止运行”；终止后保留已经复制完成的文件，并释放平台运行通道
  - 只复制文件，不修改或删除源数据；输出目录已有划分结果时会停止并提示，避免误覆盖
  - “模型训练”完整接入参考 `train.sh` 与 Ultralytics 官方配置：常用参数前置，并补充 AMP、缓存、随机种子、确定性训练、close_mosaic、定期保存、HSV、CutMix、momentum 和 warmup 等参数
  - 本次训练名称 `name` 默认留空，启动训练时自动生成 `yolo26_MMDD_HHMM`；手动填写时优先使用自定义名称
  - 数据增强区域可直接切换“工业保守、光线变化、小目标加强、遮挡与复杂背景、Ultralytics 官方默认、关闭增强”等策略；策略应用后仍可逐项微调
  - 鼠标悬停或键盘聚焦参数名旁的问号，可查看参数作用、官方范围和工业场景注意事项；SSH 密码仍只使用本机加密凭据
  - 可并行训练不同模型或参数组合；每次启动创建独立任务，任务列表可切换查看日志和单独终止。同一服务器上的相同 `project/name` 不允许同时运行，请为不同训练设置不同名称，并根据显存情况分配 `device`
  - SSH 信息留空时本地训练，填写服务器信息并测试连接后远程训练；训练作为后台长任务运行，可切换页面查看状态或随时终止
  - 远程启动前自动检查 YOLO 可执行文件、data.yaml 和输出目录；通用 `yolo` 不在 PATH 时，会根据模型名称匹配服务器上的虚拟环境
  - 训练日志持续回传，异常时显示远端最后一条真实错误，而不只显示退出码
- 制作量化数据集
  - 参考远程服务器上的 `select_calib_dataset.py`：优先保留全部非 `copy` 原始图片；不足目标数量时，再从文件名含 `copy` 的扩充图片和独立负样本目录中按比例补齐
  - 补充抽样仍兼顾类别比例与暗/中/亮场景，支持 VOC XML、LabelMe JSON 和无标注负样本，并在日志中分别显示原始、copy、负样本的可用数与选中数
  - 图片目录和标注目录均可每行填写一个服务器绝对路径；多组目录按顺序对应，未配标注目录时在图片目录内查找
  - 可设置输出目录、抽取数量（默认 128）、标注格式和随机种子；图片不足时全部抽取，结果统一为 JPG
  - 与原脚本相比，同一图片只会抽取一次，同名图片不会互相覆盖；输出目录已有文件时停止并提示
  - 默认服务器为 `dell@192.168.21.5`，先测试 SSH 连接，再点击“开始制作”；密码可加密记住，远程 Python 需安装 Pillow
  - 平台临时上传内置处理脚本，在服务器本机处理图片，结果不下载到本机；任务结束后清理临时脚本，支持终止运行
- 视频裁剪
  - 支持“开始时间 + 结束时间”“开始时间 + 持续时长”“跳过开头 + 结尾”三种方案
  - 时间可输入秒数、`MM:SS` 或 `HH:MM:SS`
  - “开始时间 + 结束时间”模式下结束时间可以留空，留空时从开始位置一直裁剪到视频结尾
  - 默认使用“原画质裁剪”：直接复制原视频、音频及其他编码流，不改变分辨率、码率和画质，文件大小通常按保留时长同比缩小
  - 原画质模式的起点受关键帧位置限制，可能与填写时间相差少量；需要逐帧准确时可选择“精确裁剪”，此模式会重新编码
  - 时间超出视频长度时自动截到结尾，每次生成新文件，不覆盖源视频
- 远程实时 AI 推理
  - 通过 SSH 密码连接 NVIDIA/Jetson 等远端推理设备，默认设备为 `192.168.1.223`、用户名为 `wel`
  - 模型和视频都从本机文件选择窗口直接选择，平台自动上传，无需预先拷贝到设备
  - 同一视频可使用 1–8 个本地 STAR/TensorRT 模型；附加模型可单独设置文件、类别名和置信度，检测结果叠加显示。模型越多，设备显存占用越高、帧率可能越低
  - 支持一键清空当前全部 STAR 模型配置；清空后自动保留一个空白模型上传窗口，方便不同任务重新配置
  - 前置功能产生的自动填充全部进入工作流待办；待办按生成顺序独立保留，不会互相覆盖，应用后在目标功能成功运行时自动清理
  - 内置 `run_star_video.py` 并自动上传，不依赖远端固定目录；也可选择本地新版脚本临时覆盖
  - 内置脚本优先通过设备驱动库直接调用 CUDA，不强制依赖 `cuda-python` 或 PyCUDA
  - 每次任务创建独立远端临时目录；停止或结束后自动删除临时脚本、模型、视频和实时输出适配器
  - 推理仍在远端 TensorRT/CUDA 环境执行，本机仅接收 JPEG 预览帧并显示带框画面
  - 默认以源视频时间轴为播放基准；多模型或设备性能不足时会自动跳过落后的源帧，因此画面可能降低到实际推理 FPS，但视频进度和动作速度保持正常
  - 暂停期间会冻结播放时钟，继续后从当前位置恢复，不会把暂停时间误算为落后时间；拖动后会重新建立播放时钟
  - 远端保存带框视频时，会用最近的检测画面补齐跳过的时间帧，保证保存视频时长与源时间段一致
  - “测试连接”和“开始实时检测”相互独立；连接测试不会上传文件或启动模型
  - 连接失败会区分密码错误、连接超时、端口拒绝、网络不可达、地址解析和 SSH 握手异常
  - 支持设置类别、置信度、IoU、最大框数、预览帧率/宽度/画质和 CUDA 后端
  - “远端保存路径”留空时只预览；填写后会同时在远端保存完整带框视频
  - 实时预览支持“撑满窗口”，可通过右上角按钮、双击画面或 `Esc` 快速切换
  - 视频预览显示当前时间/总时长，可拖动进度条跳到指定时间重新推理；旧位置的迟到预览帧会被丢弃，避免跳转后短暂回跳
  - 进度条左侧可暂停/继续播放；暂停会让远端停止读取下一帧和推理，继续后从当前位置恢复，暂停期间仍可拖动定位并预览目标帧
  - 鼠标在预览画面上移动时显示进度条，静止 3 秒后自动淡出；拖动时保持显示，键盘聚焦时也可操作
  - 视频到结尾后默认保留 120 秒供回看，可拖回前面继续检测，也可点击“结束回看并清理”；该时间可设为 0 以立即结束，对不提供时长的实时流则无法拖动
  - 如同时启用远端保存并发生跳转，已保存部分会保留，跳转后的内容写入新的 `_partN` 视频文件，避免把不连续时间段拼进同一文件
  - 预览帧与推理线程解耦，SSH 传输慢时只保留最新待发送画面，避免旧帧积压；新默认值为 20 FPS、960 像素宽、70 画质，以降低带宽压力
  - 可选择“记住 SSH 密码”：连接成功后加密保存在本机用户凭据目录，前端缓存、功能配置、命令行和日志均不包含密码
  - 未开启记忆时，SSH 密码仅用于本次身份验证，启动推理任务后立即从内存和输入框清除

远端使用步骤：首次填写设备 IP、用户名和密码，可按需开启“记住 SSH 密码”，然后点击“测试连接”。看到连接成功和设备指纹后，选择本机 `.star/.plan/.engine` 模型与视频文件，填写远端 Python 解释器（如虚拟环境中的 `bin/python`），最后点击“开始实时检测”。勾选记忆并成功连接后，同一设备、端口和用户名下次无需输入密码；“清除已保存密码”可随时删除该凭据。平台会把内置推理脚本、模型和视频自动上传到本次任务的远端临时目录，运行结束后统一清理。若需要测试新版脚本，可在“本地推理脚本”中选择其他 `run_star_video.py` 临时覆盖内置版本；连接参数发生变化后，需要重新测试连接。

远程 YOLO 数据集划分使用步骤：填写服务器 IP、端口、用户名、密码和 Python 解释器，平台会自动切换到远程模式。先点击“测试 SSH 连接”，连接成功后再在数据路径区域输入服务器上的绝对路径并点击“执行远程划分”。SSH 信息全部留空时自动恢复本地模式。远程模式不会打开本地文件选择器；日志区会显示 SSH 连接、远程路径检查、划分数量、输出目录和 `data.yaml` 路径。

量化数据集使用步骤：在左侧选择“制作量化数据集”，先选择“本地运行”或“SSH 远程服务器”。本地模式可直接选择本机文件夹并使用平台当前 Python 环境处理；SSH 模式按行填写服务器上的绝对路径，测试连接成功后执行。两种模式共用相同的抽样逻辑，输出目录均可留空（默认在第一个图片目录同级创建 `calib_dataset`）。

其他功能仍按需逐个接入。未绑定处理器的自定义功能点击“一键运行”时，系统会明确提示该功能尚未接入。

## 新增处理功能

参见 [扩展开发说明](docs/EXTENDING.md)。通常只需：

1. 编写一个接收 `RunContext` 的处理函数；
2. 调用 `register_handler` 注册；
3. 将功能配置中的 `handlerId` 绑定到该处理器。

路径、参数、一键运行和输出界面不需要重复开发。
