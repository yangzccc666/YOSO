## v26.1.4：Windows 自动标注修复

- 自动标注进程与平台统一使用 UTF-8，中文文件名、类别名和日志不再按系统 GBK 误解码。第三方异常日志字节以替代字符显示，不中断后续读取。
- 日志读取异常会明确报错并结束子进程，不再因日志线程退出、输出管道填满而无限等待；日志管道关闭后的退出等待设有上限。
- 增加环境加载、模型加载、目录扫描、每张图片开始检测／生成 XML 的进度；无新日志时每15秒显示存活等待提示（不代表已经完成推理）。不强制限时杀掉正常的慢速 CPU 推理。
- Windows 终止标注改用进程 terminate/kill，不使用 POSIX 专有的 killpg。停止时已经完成的 XML 保留。
- Windows/macOS 构建增加真实子进程 UTF-8 大量日志、异常退出、静默取消等回归测试；不等于目标用户 PT 的检出效果验收。
- 标准安装包仍不内置 PyTorch/Ultralytics。已安装 Anaconda 的用户可使用安装包附带的 `AI-Environment-Setup`，或 Release 单独的 `yolo-environment-setup.zip` 创建 CPU YOLO 环境；已有环境无需重复安装。完整解压后运行 `install_yolo_env.bat`，将输出的 python.exe 填入自动标注页的 Python 路径。详见 `setup/yolo-runtime/README.md`。

一个面向本地数据处理脚本的可视化运行壳。左侧按分组维护功能，中间配置当前功能的数据路径和参数；具体处理逻辑按需逐个接入。

视频播放快捷键：本地 PT 视频检测与远程实时 AI 推理均支持空格播放/暂停，普通预览和撑满窗口模式一致。快捷键会显示控制条，不响应长按连发；填写路径、密码、参数、使用中文输入法或打开弹窗时不会抢占空格。未开始、有待处理的控制请求、已停止或到达结尾时不发送无效播放命令。

逐帧查看：英文逗号 `,`（兼容中文 `，`）后退一帧，英文句号 `.`（兼容中文 `。`）前进一帧；控制条也有“上一帧/下一帧”按钮和原视频帧号。逐帧会自动暂停，按原视频帧号重新推理目标帧，不受预览帧率或实时跳帧影响；按空格恢复播放。到达首尾不会越界；结尾回看等待期内可逐帧后退，任务已结束则需重新开始。视频缺少有效帧率或帧数时不启用逐帧。逐帧检查画面不会混入自动保存的视频文件。

## 快速启动

桌面分发前请查看 [依赖审计与集成边界](docs/桌面分发依赖审计.md)。本机设置包含依赖清单与可选 AI Python 配置；也可运行 `python run.py --dependencies`。当前普通安装包不等于所有 AI 依赖均已集成，AI 构建配置仍需实际打包验收。

### 下载桌面版

GitHub Releases 会提供 Windows x86_64、Linux x86_64、macOS Intel 和 macOS Apple Silicon 四种安装包。下载与当前系统匹配的压缩包，解压后直接运行 `YOLO-Data-Platform`（macOS 为 `YOLO-Data-Platform.app`），无需另外安装 Python、Node.js 或项目依赖。

Conda 不是平台启动的必需条件，也不会打进发行包。只有在使用依赖用户现有 AI 环境的功能（例如本地 PT 推理、ONNX 导出或启动 X-AnyLabeling）时，才由用户自行安装并在“本机设置”中选择对应环境。

当前普通用户发行版本为 `v26.1.8`。GitHub 仅发布普通用户版，首次使用需要提供者签发的有效授权码；授权码生成和维护工具不包含在公开源码或安装包中。未签名的 Windows/macOS 程序可能触发系统安全提示；确认下载来源为本项目 Release 后，可在系统安全设置中允许本次运行。

早期更新：多文件夹抽帧、裁剪输出文件名自定义、远程 STAR 模型历史库与视频快捷键，见 [v26.1.3 更新说明](docs/RELEASE-v26.1.3.md)。

### 通用启动方式

```bash
python3 run.py
```

运行后会直接打开“YOLO数据处理平台”桌面窗口。关闭窗口时会先弹出确认框，默认选择“取消”（Esc 或直接回车均不会退出）；明确选择“确认关闭”后，本地处理服务才会停止。本地任务与实时推理可能中断；已在远端独立后台启动的训练和 TensorRT 构建继续运行。构建等待队列会保存，只有等待项时重开后默认自动执行；手动暂停或异常暂停会保留，有原远端任务待确认时先重连，确认完成后自动继续。

任务区、顶部“运行中”菜单、训练、本地／远程推理和 TensorRT 构建队列的停止／终止按钮均需二次确认；“结束回看并清理”、暂停后续队列、清空或移出等待任务同样会先确认。取消时不发送停止或队列变更请求。设置、编辑功能、分组、历史记录、待办等窗口的手动关闭也会确认，保存或选用成功后的自动关闭不额外询问；视频播放／暂停和预览撑满切换保持原有操作方式。桌面退出确认涉及 `desktop.py`，更新后需在空闲时重启平台一次生效。

桌面模式默认开启热更新。后续新增或修改功能时，后台 Python 文件以及已构建的前端界面会被自动识别并加载，不需要关闭应用重新启动；如果当时有数据处理任务正在运行，更新会安全等待到任务结束后生效。更新后当前窗口、已填写路径和本地保存的参数会继续保留。只有修改桌面外壳 `desktop.py` 或启动器 `run.py` 本身时，才需要重新启动一次。

### Windows

双击 `启动工作台.bat`。

### Linux / macOS

双击或运行 `./启动工作台.sh`。

如果提示缺少桌面组件，先执行 `pip install -r requirements.txt`。工作台只在本机内部通信，不对局域网或互联网开放。

Linux 下的搜狗/Fcitx 使用匹配平台 Qt 版本的原生输入法插件。启动器优先加载平台专用目录中的匹配插件，检查实际加载结果；缺失或不兼容时输出具体诊断，不会再错误地回退到 `xim`（Qt6 的该别名只是 Compose，并不等于搜狗兼容通道）。修复只影响平台自身，不修改系统输入法配置或重启服务。桌面启动适配需在任务空闲后重新打开平台生效；插件构建、Linux 安装包集成及临时浏览器使用方式见 [`setup/linux-ime/README.md`](setup/linux-ime/README.md)。

仍需要浏览器模式时，可以运行 `python3 run.py --web`，访问地址保持为 `http://127.0.0.1:8765`。

Linux 桌面启动时会先检查 OpenGL 上下文；不可用时自动切换 Qt 和内嵌浏览器的软件渲染，避免出现 `QRhiGles2: Failed to create context` 后白屏。仅影响界面渲染，不改变模型推理／训练的 CUDA 设备。可用 `PROCESSING_VIEW_RENDERER=software python3 run.py` 强制兼容模式，或用 `hardware` 保留硬件渲染进行诊断（默认 `auto`）。启动器也会在未显式配置系统 D-Bus 地址时，使用本机存在的系统总线套接字，避免 Conda 前缀下错误的 D-Bus 路径；不会更改系统服务、显卡驱动或会话输入法配置。

### 本机设置与换电脑运行

Windows 标准版缺少自动标注／本地推理的 AI 依赖时，已安装 Anaconda／Miniconda 的用户可将 [`setup/yolo-runtime`](setup/yolo-runtime/README.md) 整个目录复制到目标电脑，双击 `install_yolo_env.bat`。脚本联网创建独立 Python 3.11 `yolo26` 环境并安装 CPU PyTorch、Ultralytics 和 ONNX 相关依赖，验证后显示应填入平台设置的 `python.exe` 路径。已有环境默认仅检查，不自动修改；不使用或修改 base 环境的依赖。需要其他名称或修复的用法见该目录说明。新构建的安装包同时附带 `AI-Environment-Setup` 目录；已发布旧包不会因此自动更新。

顶部右侧齿轮打开“本机设置”，在“外部工具管理”中点击“添加外部工具”，填写工具名称、启动程序，以及可选的说明、工作目录、启动参数、Conda 环境和 Conda 路径。参数每行一个，不需要使用 shell 引号；启动程序应填写可执行文件而不是软件所在文件夹。保存后顶部“外部工具”下拉菜单立即同步，无需重启，重新打开也会保留。菜单中的“管理外部工具”可直接进入设置。

默认仅保留 X-AnyLabeling，并沿用已有启动配置；旧版自动内置的 Antigravity 入口隐藏，旧配置不会因打开页面而被改写，首次保存时移入配置文件的 `hiddenLegacyExternalApps`。需要时可重新添加任意工具（最多40个），支持修改名称和启动方式、移除入口，取消设置则丢弃本次修改。移除只删除配置入口，不卸载软件、不删除软件文件，也不停止已启动的程序；允许清空全部入口，重开后不会自动补回。

设置保存在当前系统的用户配置目录（Windows 为 `%APPDATA%/YOLODataPlatform`，macOS 为 `~/Library/Application Support/YOLODataPlatform`，Linux 为 `$XDG_CONFIG_HOME/yolo-data-platform` 或 `~/.config/yolo-data-platform`），不写入 Git 项目，每台电脑只需配置一次。

各功能页顶部的“保存为默认值”会把当前路径和参数保存到上述配置目录的 `function_defaults.json`，每个功能独立保存；“载入默认值”可恢复已保存配置，尚未保存过时载入功能初始值。保存后，重新打开平台优先使用保存的默认配置，临时改动需要再次点击保存才会成为新的默认值；不依赖桌面随机端口或浏览器缓存。模型训练的常用配置也包含在内，但训练设备 `device` 仍需每次手动填写，自动生成的训练名称不写回名称输入框。SSH 密码沿用原有的“记住密码”机制，明文密码和临时连接令牌不写入默认配置文件。

可使用 `PROCESSING_VIEW_CONFIG_DIR` 指定其他本机配置目录；本地 STAR 打包也可通过 `PROCESSING_VIEW_PACKAGE_TOOL` 和 `PROCESSING_VIEW_TRT_TEMPLATE` 提供机器级默认路径。SSH 密码与历史连接同样保存在当前用户配置中，不随代码仓库同步。

右上角问号支持工作与假期计时：鼠标悬停或点击显示面板，点击面板中的齿轮设置上下班时间、下班倒计时／已上班时长／同时显示、单休／双休（默认双休，单休日期可选）。下班早于上班时按跨午夜班次计算；周休从最后一个工作班次下班时开始。休息日显示距离下次上班的时间，计时按起止时间计算，包含午休。设置同样保存到本机配置文件，刷新或重新启动后沿用。

节日日期显示对应星期，例如 `2027-02-14（周日）`；多日假期显示起止日期各自的星期。星期与放假标识独立展示，节日恰逢周日不会被自动改成全民放假。

节假日数据内置于平台，离线可用，覆盖中国大陆 2026、2027 年国务院公布的放假安排和补班日期。红色为全民放假，灰色为其他节日（部分人群可能放假）；假期倒计时按日历天计算。可关闭官方调休计算，使用自己的单／双休安排。未覆盖年份会提示，需随平台更新年度数据，不会把推测的调休日期当作已公布安排。

## 当前版本

- 分组支持新建、重命名、删除和上下排序
- 功能支持跨分组移动、同组拖拽排序，以及放入“未分组”
- 删除分组只解除归属，不会删除分组内的功能
- 功能名称、路径和参数定义仍可随时修改
- 为每个功能定义任意数量的文件/文件夹路径
- 为每个功能定义文本、密码、数字、开关和选项参数
- 系统文件/文件夹选择窗口
- 普通参数值自动保存在当前应用中；密码参数只在内存中使用，不写入本地配置
- 统一的一键运行入口和运行输出区
- 不同功能可同时运行；模型训练还支持同时启动多个独立任务，可分别查看日志和终止
- 顶部“运行中 N 项”显示任务列表，可按任务单独终止；切换页面不会停止训练
- 功能页的大段使用说明收进标题／参数旁的问号提示图标：鼠标悬停或键盘 Tab 聚焦时显示，点击可固定，再点、点外部或按 Esc 关闭。浮层支持长内容滚动并自动避让窗口边缘，不会被参数表、任务列表裁掉。错误、暂停原因、任务进度、资源警告和输出路径仍直接显示。
- 顶部“运行历史”汇总所有功能最近结束的 5 条记录；所有运行中任务会置顶显示“正在运行”，不限数量且不占这 5 条名额。每个功能页面底部还会独立显示本功能最近 5 条已结束历史（成功、失败和终止），可展开查看起止时间、总耗时、输入/输出位置和日志，也可手动删除单条记录（不会删除任务输出文件）。耗时在列表直接显示，运行中实时计时，结束后固定并写入历史；旧记录从已有起止时间补算，信息不足时显示“暂无”。计时包括准备、传输、运行中暂停，排队等待不计入；训练断线重连按原始启动到平台确认结束统计，不等于纯 GPU 计算时间。某个功能的第 6 条已结束记录只会删除该功能最早的一条，不影响其他功能。本机文件为 `runtime/run_history.json`，不保存 SSH 密码
- 任务自然成功完成时显示功能名称和完成结果，约 5 秒后自动关闭；手动终止、已停止和失败任务不提醒。系统托盘不可用时使用不抢占输入焦点的非阻塞弹窗
- 当前远程训练仍依赖桌面平台保持运行，关闭平台会请求终止任务；tmux 脱离平台持久运行尚未接入
- 视频抽帧、视频裁剪、YOLO 划分和远程推理均支持终止；已完成的文件保留，裁剪临时文件会清理
- 极简处理器注册接口
- Python 一键启动的独立桌面窗口
- 桌面原生文件/文件夹选择窗口
- 后续功能支持热更新；任务运行中会延迟更新，避免中断处理

## 已接入功能

- 功能配置区域统一支持收起/展开：数据路径、通用运行参数、SSH 配置、量化数据集与模型构建/打包配置、多 STAR 模型列表等默认展开，点击标题栏即可收起。收起只隐藏内容，不清空输入或卸载控件；运行按钮、视频预览与后台任务不受影响。训练参数沿用原有分组折叠。

- 图片智能去重
  - 新增“工位工序去重（忽略背景）”：直接读取真实目录的示例图，逐工位拖动框选关注区域；仅比较目标区域，允许有限动作/标注抖动，排除旁边工位的像素干扰。支持独立区域、五档力度、保存默认值、分析统计、批量执行与回滚。属于视觉代表样本选择，不等于自动理解完整工序/异常，先分析后执行；小缺陷需特别抽查
  - 支持输入场景上层目录，开启“包含子文件夹”后自动遍历任意深度目录；每个工位的实际图片目录独立分析/去重，不跨目录比较，跳过去重备份与符号链接。保留每目录报告及批量汇总；同一上层目录可回滚最近一次实际移出文件的批量任务，停止后已完成的目录也可回滚。开关可保存为默认值；完整工序循环模式仍需单目录指定参考轮
  - 新增“差异优先去重（自动）”：不需要填写相似度阈值、最低保留比例或连续删除上限，在当前文件夹中跨非相邻画面检索已保留的代表样本；允许轻微噪声，再按原图整体及局部差异复核，变化明显或无法确认就保留。不会为了凑数量删除，也不会为了凑比例留下重复图
  - 同时提供“仅精确重复”模式，只移除完整像素一致且标注一致的图片。自动近重复是视觉启发式，不等于语义相同；低对比度微缺陷可能难以区分，重要训练数据先仅分析、抽查对照样本
  - 缩略图特征只找候选，不直接决定删除；原图尺寸、位深、标注类别/数量/位置不同或无法读取时保留。候选索引有内存/搜索上限，大数据集可能保留部分额外重复图，不会因此降低复核标准。分析报告逐张记录移除图片、保留的对照样本、原因和差异指标
  - 新增“完整工序循环去重”：通过起始图片和结束图片指定第一轮完整动作（含两端），无需视频或时间戳；参考轮以及之前的图片始终保留
  - 自然文件名排序后做变速序列对齐，默认搜索参考轮 0.4～2.5 倍张数的后续轮次，倍数可调；每张图再做局部差异复核，有差异、标注变化、来源不符或未确认完整的片段保留
  - 循环模式只与指定参考轮比较；不同工况的轮次保留，不自动作为新模板。只处理当前文件夹，不递归；文件名顺序必须对应采集顺序，建议每次处理同一视频的一组图片
  - 推荐先点击“先分析，不移动图片”，检查运行输出中的图片范围和 JSON 报告，再执行去重。力度越强越容易移除；这是画面序列匹配，不能保证识别微小缺陷或理解动作语义，重要数据请先预览
  - 参考轮最多 10000 张，最长搜索轮次最多 30000 张；动作变化不足时拒绝去重，首尾姿态难区分的边界帧可能保留。匹配后新增原图整体/局部变化复核，存在变化则整轮保留
  - 面向视频抽帧和 YOLO 训练数据，按文件名中的帧序号分组并依次分析，避免把不同视频或工序顺序混在一起比较
  - 使用画面灰度、边缘和颜色分布综合判断相似度；轻微变化会持续累积，达到差异阈值后自动保留
  - 所有模式取消最低保留比例和连续移除数量配额；旧默认配置里的这两项不再生效。连续帧旧模式仍保留首尾锚点，自动模式不强制留下重复的末帧；工序循环模式完整保留指定参考轮
  - 五档力度仅用于旧连续帧/工序循环的候选筛选，最终仍需原图复核；自动/精确模式不需要选择力度。原来显式保存的模式不会被强制覆盖，可手动切换到自动模式并保存默认值
  - 图片旁存在同名 YOLO TXT、VOC XML 或 LabelMe JSON 时，类别组合不同的画面不会互相去重，移出图片时标注文件会同步移动
  - 不永久删除文件：重复图片移入图片文件夹旁的隐藏批次目录，选择“回滚最近一次”可恢复图片和标注
- Docker ONNX 量化
  - 使用本机已有的 `onnx2quant` 容器和容器内 `onnxquant` Conda 环境运行 `easyonnxquant.tool`；容器停止时自动启动
  - 支持先执行“测试 Docker 环境”，不填写模型路径也可检查容器、Conda 和量化工具
  - 本机 ONNX、量化图片和输出目录会根据当前电脑的 Docker bind mount 自动转换为容器路径，不依赖固定磁盘目录
  - 默认 `type=yolo`、`limit=128`，支持 `mobilenet`、`custom`、minmax/entropy 和多行排除节点正则

  - 量化日志实时显示并支持终止；当前容器缺少可用的 TensorRT/CUDA 动态库时，工具可回退到 CPU 完成导出
- 远程 TensorRT 引擎构建
  - 点击“加入队列并自动执行”立即开启调度，无需再点继续队列；也支持运行中继续加入，每个 ONNX 单独排队，所有设备按入队顺序串行执行。每次保存当时的 SSH 设备、路径、精度及其他参数，不受后续编辑影响；同设备相同路径在运行／等待期间不会重复入队。主动加入新任务也会恢复手动或异常暂停的等待队列，但不会绕过未确认的远端任务。
  - 入队后清空已提交的路径输入，可继续填写下一批；页面内显示运行／等待／失败状态及独立日志。成功任务先写入运行历史，再自动移出队列，结果和日志在本功能底部或顶部“运行历史”查看，不删除远端引擎及日志文件。等待项可移除或全部清空；“暂停后续”不打断当前任务，“终止当前”会暂停后续。失败后暂停，确认盒子上没有遗留构建进程再点“继续队列”。
  - 调度在平台后端，不依赖当前页面，可切换功能。任务和等待队列保存到本机 `tensorrt_build_queue.json`；关闭平台只断开监控，不会主动停止已在远端 tmux／setsid 启动的构建。重新打开后显示“待重新连接”，点击“重新连接 / 检查结果”接管原任务，不再次启动 `trtexec`。已经结束的会检查退出码和有效 PLAN，再更新结果、历史和完成通知。
  - 重开平台时，只有等待项的队列默认自动调度；手动暂停和已知异常暂停不会因重启而绕过。有远端状态待确认时禁止启动后续任务，重连确认原任务成功结束后自动继续（手动暂停除外）。已记住的 SSH 密码沿用加密凭据库，没记住时需选择原设备并输入密码，再继续队列或加入新任务。页面明确显示“自动执行中”“等待调度”或“尚未执行／已暂停”及原因。网络中断保留待重连状态，不直接判成构建失败，只有明确退出失败或无效结果才标记失败。
  - 旧版本或本机记录丢失时，可先测试 SSH，再点击“查找远端任务”。新任务通过远端 `job.json` 找回；旧任务没有元数据时，请在 ONNX 路径框填写原路径并使用原任务根目录后再查找。若远端任务状态目录也被删除，则无法自动找回，需人工检查日志及进程。远端始终保留最小恢复信息（`job.json`、`exit.code` 等），不包含密码。
  - 等待项最多 200 条；队列另保留最近 5 条失败／终止记录，成功记录归档后自动移除。历史保存失败时保留成功记录并提示；旧版已完成卡片在确认对应历史存在后也会自动清理。每个实际执行项仍保存到功能运行历史（本功能最近 5 条）并沿用完成通知。队列接口、运行历史不保存 SSH 密码；未执行项的密码仅暂存进程内存，移除、清空或关闭时释放。
  - 可粘贴多个 AI 推理盒子上的 ONNX 绝对路径，每行一个；按选择的构建精度顺序生成 `.plan`。FP16/FP32 使用未量化 FP32 ONNX，不能使用含 Q/DQ 的量化图来恢复精度
  - FP32 构建增加 `--noTF32`；FP16 使用 `--fp16`，允许部分层回退到 FP32。`--best` 是偏性能的自动选择，不代表检测效果最佳。高精度构建前通过盒子的 `python3` 检查 ONNX 算子/类型声明，无需安装 onnx 包；检测到量化图、FP32 输入已含低精度浮点，或检查失败时停止并提示
  - 不再从本机检查或上传 ONNX；SSH 连接后在远端逐条检查，并把同名 `.plan` 和 `.trtexec.log` 生成在 ONNX 原目录
  - 开始前会统一检查远端文件和输出名冲突；中途失败时停止后续构建，已完成的 `.plan` 与日志会保留
  - 每个 ONNX 转换完成都会单独显示系统通知，内容包含当前序号、ONNX 文件名和远端 `.plan` 路径；全部完成后再显示总任务通知
  - 复用远程实时推理的 SSH 测试、设备指纹、历史连接和密码记忆；首次使用时填写当前设备的连接信息
  - 优先使用独立 tmux 会话；盒子未安装 tmux 时自动回退到 `setsid + nohup`，关闭本机平台不会终止远端构建
  - 支持 FP32、FP16、自动最佳精度、构建后性能测试、结果覆盖控制、终止任务和远端结果保留
- 本地 STAR 模型打包
  - 选择本机 TensorRT `.plan`，填写 `title`、类别名称、当前电脑的 `package_tool` 路径后完成打包
  - 可展开“命名助手与版本记录”，按 `产线-工位#主版号.次版号.修订号.mmdd` 生成名称，例如 `CT2-2#1.1.0.1117`；产线填英文标识，日期默认当天。新增标签递增主版号并清零后两位；增加数据递增次版号并清零修订号；重标或重训递增修订号。预览后点击“填入打包名称”才更新 title，仍可手填旧名称，不改变高级配置中的 model.version

  - labels 留空时仍支持原有类别识别：从 PLAN 同目录及上级目录中的 `classes.txt`、`data.yaml`、模型元数据或已有 `trt.toml` 读取并按顺序填充；PLAN 二进制本身通常不保存语义类别名
  - 类别名称支持每行一个或中英文逗号分隔，自动忽略空项并去除重复项
  - `trt.toml` 模板已内置，路径留空即可；也可指定自定义模板。运行时只生成一次性 TOML，不会覆盖原模板
  - 常改的 PLAN、title、labels 集中显示；硬件架构、CUDA 驱动、模型类型、精度、输入张量和颜色格式放在可折叠高级配置中
  - 始终在 `package_tool` 所在目录执行命令；若工具把 STAR 写到该目录，平台会自动移至 PLAN 同级目录
  - 运行前检查 PLAN、模板、可执行权限和全部 TOML 必需字段；未检测到有效 STAR 时明确报错，不会误报成功
  - 打包成功后把新生成的 STAR 路径及类别名称加入“远程实时 AI 推理”工作流待办；只有用户点击应用才会修改配置
  - 支持运行日志、终止、最近 5 条历史记录和任务完成系统通知

- Jetson ONNX 导出
  - 选择 PT 后点击“识别 PT 类别”，直接从权重内嵌 `names` 按类别 ID 读取数量和名称，可复制。多个 PT 分别显示，单个失败不影响其他模型；更换模型／Python／模型版本后旧结果自动隐藏。不会读取同目录标签文件、不修改 PT、不启动导出。

- 本地 PT / ONNX 推理检测（视频／图片文件夹）

- 视频切图

  - 顺序解码，不再每张图片都重新跳转定位。可用时通过 `ffprobe` 读取视频流的帧数／时长，校正 NVR 视频容器时长错误造成的虚假总帧数；仅对元数据矛盾的视频额外核对视频流采样包数量，不重新编码。`ffprobe` 为可选项，检查可取消且有超时，缺少时仍可顺序解码，并以实际可解码范围为准
  - 读取或保存失败也更新计划进度，并分别统计计划数、实际保存数、读取异常、保存失败及未执行项。无法继续解码时及时结束该视频，不反复读取不存在的尾部帧；异常汇总写入日志和运行历史，已保存图片保留
  - 解码器长时间没有返回时约每 5 秒显示等待状态，避免界面看似断开；FFmpeg 后端支持时设置打开／读取超时。终止请求在解码调用之间检查，原生解码器尚未返回时会明确提示等待，不强杀平台进程
  - 支持一次提交多个视频文件夹：每行一个路径，或连续点击“添加文件夹”追加，也可同时指定单个 MP4 视频。所有目录递归扫描后合并；重复目录、父子目录和相同视频会去重，避免重复抽帧。不存在的文件夹会在日志提示并跳过，其他有效目录继续处理
  - 多个目录共用当前抽帧参数和资源调度：并行数设为 0 时自动选择；资源忙时排队，内存不足时明确提示。“图片保存方式”支持“按源文件夹分别保存”（默认，同一实际父目录的视频共用结果目录）和“全部视频合并保存”（所有输入目录/子目录及单个视频汇总到一个新结果目录）。指定输出位置时在其中创建结果目录；留空时分组模式在各自源目录创建，合并模式在排序后首个视频的父目录创建。每次运行新建目录、不覆盖旧结果；视频编号避免同名视频的图片冲突，数量上限仍按每个视频计算。此选项支持保存默认值，并记录于运行历史
  - 同源视频仍可并行解码，图片通过独立视频序号区分，不会覆盖；每个视频的图片数量和失败状态独立统计，输出目录清单自动去重。重新运行创建新批次目录，保留已有结果；最大抽取数量仍对每个视频分别生效
  - 支持按每秒张数或时间间隔抽帧
  - 支持“工序时间段高密度”模式：多个工序时间段内默认按 25 帧/秒抽取，其余片段按 5 帧/秒抽取，总量默认限制为 500 张；三个参数均可调整
  - 超过总量上限时优先完整保留工序段候选图片，再从普通片段沿时间轴均匀补足；若工序段本身超过上限，则在全部工序段中均匀取满上限
  - “项目英文标识”和“场景英文标识”均可留空：两项都留空时，图片以源视频文件名（不含扩展名）为前缀，仅保留一份；只填其中一项时，另一项使用各自视频名。中文名及英文大小写保留，批量按每个视频分别处理；非法文件名字符替换为下划线，超长视频名会截短。多个同源视频的共用结果目录以已填的项目/场景标识命名，均未填时使用源文件夹名称；单视频目录沿用原命名
  - 手动填写的项目/场景标识仍按英文规则规范化；两项都填写时，输出保持全英文命名，与之前的规则兼容
  - 图片名自动记录项目、场景、视频序号、实际基础抽帧密度、视频时间点和原始帧号，例如 `tcl_191_line2_station3_video01_fps2_t000000500ms_f00000005.jpg`；小数帧率中的 `p` 代表小数点
  - 按时间间隔抽取时同时记录间隔和实际密度，例如每 `0.5` 秒一张会标记为 `every0p5s_fps2`
  - 最大抽取数量为可选项；留空时按抽帧密度和有效时间段自动决定张数
  - 可直接设置有效时间段的开始和结束时间，例如 `01:30` 至 `02:40`
  - 时间支持秒数、`MM:SS`、`HH:MM:SS`；结束时间留空表示抽到视频结尾
  - 超过上限时默认在有效区间内均匀抽取，也可选择从前往后抽取
  - 输出目录可选；留空时在原视频旁创建结果文件夹

  - 鼠标悬停或键盘聚焦参数名旁的问号，可查看常用参数作用和范围；SSH 密码仍只使用本机加密凭据
  - 可并行训练不同模型或参数组合；每次启动创建独立任务，任务列表可切换查看日志和单独终止。同一服务器上的相同 `project/name` 不允许同时运行，请为不同训练设置不同名称，并根据显存情况分配 `device`

- 视频裁剪
  - 数据路径区域新增保存方式按钮，默认“另存为新视频”；“替换原视频（自动备份）”保持原路径与文件名，运行前再次确认。替换模式忽略另存目录/名称，不能同时拆分训练/测试集；支持 MP4、M4V、MOV、MKV，其他容器请另存 MP4

  - 另存模式可关闭精确时间裁剪，继续使用“原画质裁剪”，直接复制原视频、音频及其他编码流，不改变分辨率、码率和画质，文件大小通常按保留时长同比缩小；但起止边界受关键帧限制，无法保证与所选时间严格对应
  - 精确模式遇到超出视频长度的结束时间会报错，留空结束时间仍表示到视频最后。保留旧脚本直接调用时未传 `clip_exact_time` 的快速模式兼容行为
- 远程实时 AI 推理
  - 通过 SSH 密码连接 NVIDIA/Jetson 等远端推理设备；设备地址和用户名不再写死，可从历史连接中选择

  - 每次任务创建独立远端临时目录；停止或结束后自动删除临时脚本、模型、视频和实时输出适配器
  - 推理仍在远端 TensorRT/CUDA 环境执行，本机仅接收 JPEG 预览帧并显示带框画面
  - 默认以源视频时间轴为播放基准；多模型或设备性能不足时会自动跳过落后的源帧，因此画面可能降低到实际推理 FPS，但视频进度和动作速度保持正常

  - 远端保存带框视频时，会用最近的检测画面补齐跳过的时间帧，保证保存视频时长与源时间段一致

  - 连接失败会区分密码错误、连接超时、端口拒绝、网络不可达、地址解析和 SSH 握手异常
  - 支持设置类别、置信度、IoU、最大框数、预览帧率/宽度/画质和 CUDA 后端
  - 每个模型的“读取类别”按钮可直接从本机 STAR 的内嵌 `model.labels` 读取类别，按类别 ID 顺序填入该模型的逗号分隔输入框；无需 SSH 或 CUDA，不修改模型、其他模型或置信度。读取期间修改配置会取消填充，失败保留原类别；不猜测文件名或邻近数据集，PLAN/engine 和无类别元数据的文件需手动填写
  - 模型区域提供“历史模型”弹窗：启动推理时自动保存全部模型的本机文件路径、类别名称及置信度，支持按文件名、路径或类别搜索并一键填回。历史模型长期保存，不受 5 条运行历史限制；移除或清空当前模型不会删除历史
  - 历史弹窗也可“保存当前配置”，用于保存尚未运行的模型；同一路径和同一类别顺序重复使用只更新记录，不同类别配置分别保留。选择时优先填空位，否则追加，最多 8 个，不覆盖其他模型；文件已移动或删除会提示不可用，不自动丢弃记录。删除历史仅删除元数据，不删除实际模型文件
  - “远端保存路径”留空时只预览；填写后会同时在远端保存完整带框视频
  - 实时预览支持“撑满窗口”，可通过右上角按钮、双击画面或 `Esc` 快速切换
  - 逐帧按钮支持点按一帧，按住约 350 毫秒后连续前进/后退；每次等待上一帧请求完成，再按设备速度继续，不堆积请求。松开、移出按钮、切换窗口、到达首尾或发生错误后停止，画面保持暂停；已发出的当前帧请求可能在松开后完成。本地 PT 预览共用同样的交互
  - 视频预览显示当前时间/总时长，可拖动进度条跳到指定时间重新推理；旧位置的迟到预览帧会被丢弃，避免跳转后短暂回跳
  - 进度条左侧可暂停/继续播放；暂停会让远端停止读取下一帧和推理，继续后从当前位置恢复，暂停期间仍可拖动定位并预览目标帧
  - 远程视频的右上角撑满/退出按钮与底部进度条采用低不透明度背景，不再模糊遮挡画面；静止 3 秒后一起淡出并隐藏鼠标指针，移回画面或使用键盘即可唤回。拖动、长按逐帧期间保持显示，松开后恢复计时；键盘聚焦控件时保持可操作，Esc 始终可退出撑满。不再在整幅画面上触发原生快捷键提示框
  - 视频到结尾后默认保留 120 秒供回看，可拖回前面继续检测，也可点击“结束回看并清理”；该时间可设为 0 以立即结束，对不提供时长的实时流则无法拖动
  - 如同时启用远端保存并发生跳转，已保存部分会保留，跳转后的内容写入新的 `_partN` 视频文件，避免把不连续时间段拼进同一文件
  - 预览帧与推理线程解耦，SSH 传输慢时只保留最新待发送画面，避免旧帧积压；新默认值为 20 FPS、960 像素宽、70 画质，以降低带宽压力
  - 可选择“记住 SSH 密码”：连接成功后加密保存在本机用户凭据目录，前端缓存、功能配置、命令行和日志均不包含密码
  - 未开启记忆时，SSH 密码仅用于本次身份验证，启动推理任务后立即从内存和输入框清除

远端使用步骤：首次填写设备 IP、用户名和密码，可按需开启“记住 SSH 密码”，然后点击“测试连接”。看到连接成功和设备指纹后，选择本机 `.star/.plan/.engine` 模型与视频文件，填写远端 Python 解释器（如虚拟环境中的 `bin/python`），最后点击“开始实时检测”。勾选记忆并成功连接后，同一设备、端口和用户名下次无需输入密码；“清除已保存密码”可随时删除该凭据。平台会把内置推理脚本、模型和视频自动上传到本次任务的远端临时目录，运行结束后统一清理。若需要测试新版脚本，可在“本地推理脚本”中选择其他 `run_star_video.py` 临时覆盖内置版本；连接参数发生变化后，需要重新测试连接。

远程 YOLO 数据集划分使用步骤：填写服务器 IP、端口、用户名、密码和 Python 解释器，平台会自动切换到远程模式。先点击“测试 SSH 连接”，连接成功后再在数据路径区域输入服务器上的绝对路径并点击“执行远程划分”。SSH 信息全部留空时自动恢复本地模式。远程模式不会打开本地文件选择器；日志区会显示 SSH 连接、远程路径检查、划分数量、输出目录和 `data.yaml` 路径。

量化数据集使用步骤：在左侧选择“制作量化数据集”，先选择“本地运行”或“SSH 远程服务器”。本地模式可直接选择本机文件夹并使用平台当前 Python 环境处理；SSH 模式按行填写服务器上的绝对路径，测试连接成功后执行。两种模式共用相同的抽样逻辑，输出目录均可留空（默认在第一个图片目录同级创建 `calib_dataset`）。

其他功能仍按需逐个接入。未绑定处理器的自定义功能点击“一键运行”时，系统会明确提示该功能尚未接入。

## 运行历史的任务标识

全局历史与各功能历史使用相同的摘要：标题显示功能名及本次处理的文件／文件夹，下面直接显示关键参数和源路径，再显示日期、状态和耗时。训练保留本次训练名称；批量输入展示前两个对象及总数量，长名称允许换行，完整路径可悬停查看，展开后仍可查看所有详情与日志。

新运行会记录当时的关键参数快照（例如抽帧频率、裁剪区间、训练轮次或推理置信度），只保存明确允许的参数，不保存 SSH 密码。旧记录直接从已有路径、模型或输出信息生成标识，不改写历史文件；以前未保存的参数无法补回。完全缺少对象信息时显示短记录编号，日期时间仍用于区分重复运行。

## 加班记录

右上角问号的“工作与假期”面板可查看加班记录、今日／本月已确认时长；齿轮中的“计时设置”可开关自动记录，并设置无操作等待时间（10／20／30／60 分钟，默认 30 分钟）。沿用上下班时间、单双休及中国节假日／调休设置，也支持跨午夜夜班。

- 非工作时间在平台内进行真实的鼠标、键盘等前台操作时开始记录；后台训练、视频刷新和状态轮询不续计活动。
- 连续无操作达到等待时间后，本段暂时结束，结束时间回退到**最后实际操作时间**，保存为“待确认”，不计入已确认汇总。关闭平台时不继续无限累计；下次启动会根据已保存的最后操作时间恢复待确认状态。
- 返回后可选择“确认已下班”、通过“修正时间”填写真实起止时间，或选择“刚才一直在加班”补回空档并继续。自动衔接只允许最近一段、24 小时以内且未跨正常班次的记录；其他情况请修正时间。修正后的时段若包含正常上班时间，该部分不会计入加班。
- “结束加班”需确认，保存为已确认；同一天后续点击不会立即重新开始，需要时可手动“开始新一段加班”。待确认和已确认历史均可修正，重叠或未来时间会被拒绝。
- 每段有效加班不足 60 分钟不计入汇总，确认后不显示在历史列表；达到 60 分钟则整段计入（不是扣除前一小时）。多个独立短时段不累加凑满一小时。待确认的短时段暂时保留，方便修正或衔接；已有历史同样按此规则展示，底层原始数据不会被破坏。
- 设置与记录保存在当前电脑的用户数据目录（`overtime.json`），重开保留，不上传服务器。仅反映平台使用情况，无法判断你在其他软件中是否仍在工作，属于个人估算，不是正式考勤。

## 新增处理功能

参见 [扩展开发说明](docs/EXTENDING.md)。通常只需：

1. 编写一个接收 `RunContext` 的处理函数；
2. 调用 `register_handler` 注册；
3. 将功能配置中的 `handlerId` 绑定到该处理器。

路径、参数、一键运行和输出界面不需要重复开发。
